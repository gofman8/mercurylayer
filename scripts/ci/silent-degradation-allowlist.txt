#
# Every line below is a swallow site that has been READ and whose FAILURE DIRECTION has been
# decided. The question that decides it, and the only one that matters:
#
#     if this expression fails, does the code end up doing MORE WORK or LESS PROTECTION?
#
# MORE WORK is fine (re-attempting an idempotent booking, quarantining a coin, rejecting a transfer,
# throttling a faucet, returning a too-low estimate that makes MORE coins eligible). LESS PROTECTION
# is the bug this repo keeps re-growing: an empty carrier set that reads as "no carriers to
# protect", an empty UTXO vector that reads as "spent", an absent deadline that reads as "nothing
# due", an empty branch-witness set that reads as "no exit branch to broadcast".
#
# FORMAT  (TAB-separated; the reason MUST be a `#` comment directly above the entry)
#
#     # <why this one is safe, in terms of the direction it fails toward>
#     <count><TAB><path from repo root><TAB><pattern-id><TAB><the normalised source line>
#
# `count` is how many times that exact line appears in that file. A SECOND identical swallow in the
# same file is a new site and fails the guard until the count is raised deliberately.
#
# Keyed on the normalised LINE, not the line number, so unrelated edits above it do not churn this
# file and two sessions editing one file do not collide.
